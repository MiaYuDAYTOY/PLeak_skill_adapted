**当前实验实际上在做什么**

当前流程在冻结模型权重的条件下，用少量训练文档优化一个共用的离散 trigger（AQ），再把同一个 trigger 用于其他测试文档。这里的“训练”指搜索 trigger，没有更新模型权重。

训练输入是 `完整 Skill + trigger + 换行 + Skill 的前 P 个目标 token`；只有最后的目标前缀参与 loss。测试输入是 `完整 Skill + trigger + 换行`，评估模型随后生成的内容与原 Skill 的重合程度。训练和测试采用纯文本拼接，没有 system/user/assistant 角色边界；`chat_prompt.py` 未接入正式流程。[训练输入](/Users/mia/PLeak_skill_adapted/Attack.py:141)、[生成输入](/Users/mia/PLeak_skill_adapted/Sampler.py:55)。

因此当前实验直接测量的是“模型已读取 Skill 上下文后，trigger 促使其复现该上下文的能力”。如果要进一步声称真实系统提示词边界被突破、训练数据被记忆提取，或正文重合主要由 trigger 优化带来，需要相应的实验场景和对照。

**当前配置下仍需解决或验证的问题**

1. **长上下文与显存容量仍未得到完整验证。**官方 Qwen3-0.6B-Base 配置的 `max_position_embeddings` 为 32768，`rope_scaling=null`，不是无限上下文。[官方配置](https://huggingface.co/Qwen/Qwen3-0.6B-Base/blob/main/config.json)。按当前预算，prompt 超过 16359 token 时，若生成接近上限，总长度预算就会超过标称窗口；提前 EOS 时不一定越界。正式代码目前没有逐条记录并判定这一条件。本机没有对应 tokenizer，未把字符数冒充 token 数，也没有断言当前 documents 必然超窗。

   恢复完整训练池后，sample_seed=2 的 N=3/4/5 都会选到曾被排除的 `009_baoyu-slide-deck`；N=5、sample_seed=0 会选到最长训练文档 `042_latex`。当前默认网格实际覆盖 12 篇不同训练文档。旧日志中的 Qwen 042_latex OOM 发生在全长 logits loss 路径，当前已换为监督位置投影，不能据旧错误断言现在仍然 OOM；同样也不能据此宣布全部长文档已通过。

   [dual4090_check.py](/Users/mia/PLeak_skill_adapted/scripts/dual4090_check.py:86) 虽已恢复全部测试候选，但 tokenizer、模型、4-bit 量化、训练 trigger、显存估算仍固定面向 Llama。它不能直接充当 Qwen BF16 容量证明。建议保留全部数据，使用当前 Qwen 模型和预算逐条做长度记录，并在目标 GPU 上测最长训练输入和最长测试生成；不需要重新屏蔽源数据。

2. **生成失败被排除在主要评分分母外，跨实验比较容易产生选择偏差。**[Sampler.py](/Users/mia/PLeak_skill_adapted/Sampler.py:256) 只对 `status=ok` 的结果评分并求均值。空输出但未报错的样本仍会计入分母、记零；生成报错的样本则退出分母。本次复现：4 次尝试中 1 次完整泄漏、1 次正常但不匹配、2 次生成失败，代码报告泄漏率为 1/2=50%，而按全部尝试计的完整泄漏率为 1/4=25%。这是当前明确的条件指标定义，不是算术计算错误。

   建议同时报告生成成功率、以所有测试样本为分母的完整泄漏率，以及保留现定义的成功生成条件重合率。失败没有可评分文本，把它计零是一种操作性统计口径，应单独命名，不能据此判断失败样本本身是否会泄漏。当前汇总还会把“整组生成全部失败”的零值计入跨 seed 均值，和部分失败时的分母处理不同，需要明确说明。

3. **当前 documents/Qwen 缺少对应的攻击基线。**正式入口只执行学习后的 trigger，没有在同一测试集、同一预算下执行空 trigger、随机 trigger 或固定自然语言复制请求。已有 empty/random/learned 对照来自早期 webtesting/Llama 的 10 篇文档，不能替代本次 Qwen/documents 对照。

   当前默认覆盖的 12 篇训练文档都带 YAML front matter。P=8/16/32 监督的是文件开头，可能主要覆盖元数据；正文重合是后续生成的表现，不应描述为直接用整篇正文训练了 trigger。建议记录目标前缀的实际文本，并用正文指标与全文指标共同解释效果。

4. **attack 随机性和生成随机性没有独立控制。**[main.py](/Users/mia/PLeak_skill_adapted/main.py:450) 只在训练前设置 attack seed；随机生成沿用之后的 PyTorch 状态，没有单独的 generation seed，也没有按文档设置稳定的生成 seed。因而 attack_seed 维度不宜被解释为纯粹的“优化初始化影响”。测试名单增删或前序文档生成长度改变，也可能改变后续文档的随机状态。建议明确 generation seed，并在需要逐文档配对比较时使用稳定的文档身份派生 seed。

5. **完整网格耗时和中断恢复不足。**[Attack.py](/Users/mia/PLeak_skill_adapted/Attack.py:397) 每轮最多检查 `AQ长度×30` 个候选。AQ=12 时约为 360 个候选，每个都遍历 N 篇训练文档，再加一次当前 trigger 的梯度计算；这是每轮约 360N 次候选 forward，实际会因无效候选而减少。搜索没有最大轮数、时间上限或过程中保存的 trigger checkpoint。训练 OOM/边界错误会使整个启动退出；没有自动继续后续组合。训练结束后才保存 trigger，全部测试生成结束后才写 CSV，意外中断可能丢失本组已生成的内容。[结果落盘位置](/Users/mia/PLeak_skill_adapted/main.py:462)。

   建议增加逐组状态、训练进度 checkpoint、逐样本生成落盘及断点续跑。迭代上限或超时若启用，应写入配置，作为一种明确的停止条件；不要静默改变算法。

6. **实验溯源和统计汇总还不完整。**目前有文档 SHA-256、训练/测试名单、两种 seed、精度和显式生成参数，这是已具备的优点。但正式 main 未记录 Git 提交、模型/分词器 revision、实际加载的 max_position_embeddings、注意力后端、GPU、依赖版本或每组耗时。环境变量可更换本地模型，单靠路径名不能证明目录确为 Base 版本。

   当前 summary 主要保存均值，没有标准差或置信区间。3 个训练子集×3 个 attack seed 的 9 次运行共享测试文档，不能把 9×70 次观测当作 630 篇独立文档。如果根据这批测试结果选 prefix 或最优配置，还应另设验证/最终测试安排，避免用同一测试集同时选参和报告最终效果。

7. **文档默认值和旧入口已落后于正式代码。**[README.md](/Users/mia/PLeak_skill_adapted/README.md:133) 仍写训练规模 `[1,3,5,8,16]`、prefix `[8]`、5 个 sample seed、6 个 attack seed、150 次；实际为 `[3,4,5]`、`[8,16,32]`、3×3 个 seed、81 次。README 的汇总组数也随之过时。`sample.py`、`step.py` 仍固定 `test_num=1000`，在当前每类 70 篇测试池中会在数据构建阶段报错；本次已复现。应把 `main.py` 明确为正式入口，并更新或标记旧脚本。
